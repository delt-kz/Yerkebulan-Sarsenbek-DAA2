# Kadane Algorithm: Theoretical and Empirical Study

## Algorithm Overview
Kadane's algorithm addresses the maximum subarray problem: given an array of integers (which may include negatives), the goal is to identify the contiguous segment whose elements sum to the largest possible value. The implementation in this project follows the canonical dynamic programming insight that any optimal solution ending at position `i` either extends the optimal solution ending at `i-1` or starts anew at `i` if the previous running sum is negative. The algorithm streams through the input exactly once while maintaining four scalar state variables: the `currentSum` representing the best sum of a subarray ending at the current index, the `bestSum` seen so far, and the corresponding `start`/`end` indices for reconstruction of the solution interval. Whenever the running sum dips below zero, the algorithm resets the candidate subarray to the next index, effectively discarding prefixes that would only decrease future totals. The inclusion of tie-breaking logic ensures deterministic selection of the longest maximum-sum subarray when multiple ranges share the same aggregate sum, which is important for reproducibility in benchmarking scenarios. The codebase also provides a brute-force solver that enumerates every `O(n^2)` subarray; this serves both as a correctness oracle for unit tests and as a conceptual baseline illustrating the dramatic improvement achieved by Kadane's linear-time refinement. Together with a CLI benchmarking harness, these components form a complete workflow for studying algorithmic behavior from theory through measurement.

## Complexity Analysis
The complexity of Kadane's algorithm can be derived by counting the number of primitive operations as a function of the input size `n`. Each iteration of the outer loop performs a constant amount of work: one array access, a constant number of comparisons, and updates to scalar variables. Because the loop ranges from `0` to `n - 1`, the total number of iterations equals `n`, yielding a tight upper bound of `T(n) = an + b` for constants `a` and `b`. By definition, this linear function satisfies `T(n) ∈ Θ(n)` and, since the coefficient `a` is positive, also implies `T(n) ∈ O(n)` and `T(n) ∈ Ω(n)`. More formally, we can assert that there exist constants `c1`, `c2`, and `n0` such that `c1·n ≤ T(n) ≤ c2·n` for all `n ≥ n0`, confirming tightness. The best, average, and worst-case running times coincide because the control flow does not branch on global input structure (e.g., sortedness); every input triggers exactly one pass through the loop and therefore the same asymptotic cost. Although constant factors may vary slightly depending on data-dependent branches (for example, whether `currentSum < 0`), these differences do not alter the asymptotic classification.

For space complexity, Kadane's algorithm operates in-place aside from a handful of scalar variables and the immutable result object. The algorithm reads from the input array without allocating additional arrays or collections, so the auxiliary space remains constant: `S(n) = c`, which lies in `Θ(1)`, `O(1)`, and `Ω(1)`. The overall memory footprint is therefore dominated by the input itself, which is treated as part of the problem specification and not counted toward auxiliary space. In contrast, the brute-force solver employs nested loops that still require only `Θ(1)` auxiliary space (no extra arrays are created), but it performs `n(n + 1)/2` inner-loop iterations. Summing the arithmetic series yields `T_bruteforce(n) = Θ(n^2)`, with the quadratic term arising from the double loop over all start–end pairs. This quadratic behavior makes the brute-force approach impractical for large `n` and highlights the efficiency of Kadane's linear-time algorithm.

To expand on the time-complexity derivation, consider the recurrence relation for the running sum: `currentSum_i = max(array[i], currentSum_{i-1} + array[i])`. Evaluating this recurrence for each element requires constant work, leading to `T(n) = T(n-1) + 0(1)`. Unrolling the recurrence yields `T(n) = T(0) + n·Θ(1)`, which simplifies to `Θ(n)`. This also demonstrates that Kadane's algorithm can be interpreted as a dynamic programming solution that computes optimal substructure values in linear time. Finally, because the algorithm maintains indices to reconstruct the maximum subarray, the memory requirements remain constant regardless of array length; no additional data structures proportional to `n` are introduced at any step.

## Empirical Results
To validate the theoretical complexity, the project includes a benchmarking tool that synthesizes arrays under multiple distributions (uniform random, sorted, reverse-sorted, nearly sorted, and a worst-case pattern) and records execution times in nanoseconds. Measurements follow a warmup-and-measure pattern to reduce JVM startup noise, and they are aggregated via the performance tracker, which reports average, minimum, and maximum durations per configuration. The sample dataset in `data/kadane-benchmarks.csv` reflects runs on arrays of size 100, 1 000, and 10 000, with average durations clustering tightly around linear growth: increasing the input by a factor of ten increases runtime by roughly 6–10×, consistent with the `Θ(n)` prediction. Even the artificially constructed worst-case distribution, where all elements are `-1` except a trailing `+1`, shows only modest overhead compared to random inputs because Kadane's control flow remains unchanged. Constant factors do vary across distributions: nearly sorted arrays with small positive drift execute faster than random sequences due to fewer resets of the running sum, while worst-case arrays incur extra branch mispredictions and longer stretches of negative partial sums, illustrating how microarchitectural considerations influence practical performance despite identical asymptotic bounds. The CSV can be regenerated by invoking the CLI (for example, `mvn -q exec:java -Dexec.mainClass=cli.BenchmarkRunner`), and the resulting statistics provide an empirical anchor for the theoretical analysis, confirming that the linear-time algorithm scales smoothly while the quadratic baseline would become infeasible for the largest input sizes if executed.
